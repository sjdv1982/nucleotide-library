## Description

This library has been generated by fragment clustering, using RMSD after superposition as the pairwise distance criterion.

What has been clustered is a collection of RNA dinucleotide/trinucleotide fragments. This collection was previously built by collecting all protein-RNA complexes from the PDB, extracting all RNA chains that form biological interfaces, cutting them into dinucleotides and trinucleotides, and removing redundancies (by a pre-clustering at 0.2 A). For each fragment, the PDB origin (PDB code provenance) has been kept.

The library is a list of fragment clusters, obtained by repeatedly identifying and removing the largest cluster. The library conformers are described as: the coordinates of the fragment cluster heart, plus the PDB origin of the entire cluster.

## Contents

### ./library/

This folder contains the conformers and PDB origins (i.e. provenance) of each conformer of the library.

There is a library of dinucleotides and a library of trinucleotides.
Each library has three levels of precision: 0.5A, 1.0A and 2.0A. These correspond to different superposition RMSD cutoffs that were used for clustering.

The library fragment conformers are in Numpy format, containing only the coordinate xyz values.
For the corresponding PDB files, see <https://github.com/sjdv1982/nucleotide-fragment-templates>

The conformers and origins files are specified separately for each sequence motif:

- dinucleotide library: sequence motifs AA, AC, CA, CC
- trinucleotide library: sequence motifs AAA, AAC, ACA, ACC, CAA, CAC, CCA, CCC  

For each precision level, for each sequence motif, there are three coordinate files:

- The primary fragments coordinates. This file contains coordinates of the heart of each cluster with multi-PDB origin. File name: `[di/tri]nuc-<motif>-<precision>.npy`.

- The replacement fragments coordinates, of the same length as the primary coordinates. For each cluster, it contains the closest fragment that comes from a different PDB than the cluster heart. This can be used to replace the cluster heart when modeling one of the PDBs that was used to build the library. File name: `[di/tri]nuc-<motif>-<precision>-replacement.npy`. A separate file contains, for each cluster: the PDB origin of the heart fragment, of the replacement fragment, and the RMSD between both fragments. File name: `[di/tri]nuc-<motif>-<precision>-replacement.origin.txt`

- The extension fragments coordinates. These fragments are *singletons*, i.e. they do not form multi-PDB clusters because they are seen in only one PDB. (If that PDB is being modeled, the extension fragments that come from that PDB must be filtered out). The extension fragments have been shown to improve the closest fit of *other* singletons, i.e. at a precision level that is poorer than the library precision. File name: `[di/tri]nuc-<motif>-<precision>-extension.npy`. A separate file contains the PDB origin: `[di/tri]nuc-<motif>-<precision>-extension.origin.txt`

Note that the sequence motifs contain only A and C. The `mutate.py` command-line tool can be used to generate coordinate files for other sequence motifs by mutating A into G and C into U. The `lib-mutate.py` script generates coordinate files (and copies the origins files) for all sequence motifs containing G and U, at all levels of precision, for both libraries.

### ./output/

The output files generated by the library pipeline. As explained above, the input of the pipeline is a coordinate array of non-redundant fragments. All files in the `output/` folder contain fragment indices (starting at 1) that refer to this input array.

The following files are present:

- The clustering results at 0.5A, 1.0A and 2.0A (`*.clust` files)
- The indices of the primary, replacement and extension fragments (`*-indices.txt` files)
- The analysis results of computing the "closest fit" (i.e. nearest neighbour) of each of the input fragments, using the clustering files to speed up the calculation (`closest-fit/` folder).
